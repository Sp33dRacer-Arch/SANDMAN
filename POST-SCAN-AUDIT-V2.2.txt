REAL ISSUES FOUND AND FIXED
---------------------------
1. Light-mode persistence script was inline and would be blocked by the production Helmet CSP.
   FIX: removed inline scripts, set HTML default to data-theme="light", and restored saved theme from external app.js.

2. Default light-mode buttons initially advertised the wrong action before deferred JavaScript ran.
   FIX: initial icons/labels now correctly offer Dark mode while the page starts light.

3. Blank optional Cloudinary variables could fail environment parsing instead of behaving as unconfigured.
   FIX: blank/whitespace Cloudinary values normalize to undefined.

4. Seller listing edits could delete and recreate ProductFitment rows, destroying admin verification metadata.
   FIX: unchanged fitments are preserved; only removed fitments are deleted and only new fitments are created.

5. Seller editing could still drop existing fitments that were not represented in the seller's current Garage.
   FIX: non-Garage existing fitments are preserved in the submitted edit payload.

6. Seller Sales showed too little destination information for fulfilment.
   FIX: full paid-order shipping address is shown only to the seller who owns the marketplace line.

7. First-time payout setup silently defaulted the connected-account country to ZA.
   FIX: seller must enter a valid two-letter legal seller country before account creation.

8. Seller-profile bio frontend limit did not match the backend.
   FIX: both now use the backend 1000-character limit.

9. Long uploaded filenames could produce alt text longer than the API accepts.
   FIX: generated image alt text is capped to 240 characters.

10. Saved phone numbers were not returned by normal login/refresh public-user payloads.
    FIX: public user payload now includes phone, so Profile & Settings can display an existing saved phone number.

11. Image URL fields accepted non-HTTPS URLs that the production CSP would not display.
    FIX: marketplace/admin APIs and both browser UIs now require HTTPS image URLs.

12. New seller/profile inputs had several frontend/backend constraint mismatches.
    FIX: relevant maxlength/min/max values are aligned with the Zod API schemas.

KNOWN REMAINING INTEGRATION / NON-BLOCKING RISKS
------------------------------------------------
- Stripe Connect seller onboarding still uses the project's existing Accounts v1 flow. The user's Stripe account has already reported an Accounts v1 compatibility error. This patch does not migrate Connect to Accounts v2.
- Removing an image from SANDMAN removes the database reference but does not yet delete the corresponding Cloudinary asset. Abandoned/partially failed uploads can therefore leave orphaned Cloudinary files.
- Browser-side file type/10 MB checks improve UX, but a hostile authenticated client could bypass browser validation. For stronger production abuse controls, configure Cloudinary-side upload restrictions/presets/quotas as well.
- Native browser prompt()/confirm() dialogs still exist in older non-media flows (reviews, some security/support actions).
- No real browser/E2E, Railway runtime, Cloudinary credential, Stripe, or payment test was possible in this static container scan.
