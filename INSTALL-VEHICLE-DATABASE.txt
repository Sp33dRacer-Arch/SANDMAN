SANDMAN VEHICLE DATABASE V1
===========================

WHAT THIS DOES
--------------
Adds a large, reusable vehicle-catalogue importer to your EXISTING SANDMAN backend.
It does NOT replace your Garage. It fills the existing Prisma VehicleVariant table
that Garage/fitment already uses.

Included:
- Curated global supplement: 355 model ranges, expanded into model-year rows.
- Important South African / European / Japanese models not reliably covered by US-only data.
- BMW M140i (2016-2019) is included.
- NHTSA vPIC importer for much larger model-year coverage.
- Resume/checkpoint support for long NHTSA imports.
- Dynamic Prisma schema detection so it adapts to your existing VehicleVariant fields.
- No .env changes.
- No historical migration edits.

IMPORTANT
---------
A vehicle appearing in the catalogue does NOT prove that a product fits it.
Keep ProductFitment/fitment rules as the authority for compatibility.

INSTALL INTO YOUR MAIN BACKEND
------------------------------
1) Extract this ZIP.

2) In PowerShell, overlay it onto:
   C:\Users\asand\Downloads\SANDMAN-backend

Example, if extracted to Downloads:

robocopy "C:\Users\asand\Downloads\SANDMAN-VEHICLE-DATABASE-V1" "C:\Users\asand\Downloads\SANDMAN-backend" /E /XD .git node_modules /XF .env /R:1 /W:1

3) Open the project:

cd "C:\Users\asand\Downloads\SANDMAN-backend"

4) Make sure your LOCAL database is running, then verify Prisma:

npx prisma generate
node --env-file=.env scripts\vehicle-catalog-check.mjs

FAST IMPORT - CURATED GLOBAL CATALOGUE
--------------------------------------
This requires no external vehicle API and is the best first test:

node --env-file=.env scripts\sync-vehicle-catalog.mjs --source=curated --from=1996 --to=2027

To test only BMW first:

node --env-file=.env scripts\sync-vehicle-catalog.mjs --source=curated --only-make=BMW --from=1996 --to=2027

Then:

node --env-file=.env scripts\vehicle-catalog-check.mjs

Now search Garage for:
BMW M140i

LARGE IMPORT - CURATED + NHTSA POPULAR MAKES
---------------------------------------------
NHTSA is an internet API, so this can take a while:

node --env-file=.env scripts\sync-vehicle-catalog.mjs --source=both --mode=popular --from=1996 --to=2027 --delay=250

MAX IMPORT - ALL NHTSA MAKES
-----------------------------
This can take hours and NHTSA rate-controls traffic. The script saves a checkpoint
after every make/year so you can stop it with Ctrl+C and run the SAME command later.

node --env-file=.env scripts\sync-vehicle-catalog.mjs --source=nhtsa --mode=all --from=1996 --to=2027 --delay=350

If you intentionally want to restart the NHTSA import from zero:

node scripts\vehicle-sync-reset.mjs

DRY RUN
-------
Shows how the importer maps data without writing rows:

node --env-file=.env scripts\sync-vehicle-catalog.mjs --source=curated --only-make=BMW --dry-run

RAILWAY / PRODUCTION
--------------------
Do NOT blindly point your local command at Railway's private postgres.railway.internal
hostname; that hostname only works inside Railway's network.

First verify locally. Then run the same importer from inside the deployed Railway
service, or use Railway's approved public PostgreSQL connection for a one-off import.
Do not add this huge sync to every normal app startup.

SOURCE NOTES
------------
- NHTSA vPIC is official U.S. government vehicle/manufacturer data.
- vPIC is strongest for vehicles intended for U.S. sale/import.
- SANDMAN_CURATED supplements obvious global / South African / European / JDM gaps.
- Engine/trim coverage is not exhaustive. VIN decode can be added as the next layer.
